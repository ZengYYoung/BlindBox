# BlindBox 接入、联调与部署指南

> 本轮没有启动 MySQL、Redis 或 Docker，没有执行迁移、种子导入和实际交易。以下是后续操作手册。先使用独立开发库，现有 SQLite/MySQL 数据不会自动迁移或覆盖。

## 1. 组件关系与前置环境

- 前端：Node.js 22+、npm；React + Vite，开发端口 5173。
- 后端：JDK 17+、Maven 3.9；Spring Boot 3.4.4，默认端口 8080。
- 数据库：MySQL 8.4 / InnoDB；使用 MySQL 锁定读取、CHECK 和 Flyway DDL。
- Redis：Redis 7.x；列表缓存、Lua 固定窗口限流，不存交易库存和余额。
- 可选：Docker Compose、Nginx、k6。模板已保存，本轮未构建、启动或压测。

浏览器访问 Vite：/api、/uploads 代理到 localhost:8080，/images 由前端 public 提供。容器内 backend 必须使用 mysql/redis 服务名，不能写 localhost。生产 Nginx 同源转发接口。

## 2. 只看界面，不连接部件

项目根目录执行：

~~~bash
cd BlindBox-frontend
npm ci
VITE_CATALOG_PREVIEW=true npm run dev
~~~

访问终端 URL。此模式提供明确标注的样例商品、图片、库存和计算概率；抽奖按钮禁用，账户/社区不提供假交易。正常联调停止该进程，改为 npm run dev，并确保 .env.local 中没有启用预览。

predev/prebuild 自动复制根目录 images 中的 32 个 PNG 到 public/images，不修改原图片。新增 PNG 后执行 npm run assets。图片原件较大，正式公开站点可另外制作多尺寸资源并使用 CDN。

## 3. 配置本机 MySQL

使用已有 MySQL 即可。登录管理账号：

~~~bash
mysql -u root -p
~~~

手动执行并替换密码：

~~~sql
CREATE DATABASE blindbox CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'blindbox'@'localhost' IDENTIFIED BY '填写你自己的密码';
GRANT ALL PRIVILEGES ON blindbox.* TO 'blindbox'@'localhost';
~~~

这是开发账号，需要 Flyway DDL 权限。生产应由独立迁移账号执行 DDL，运行账号仅授予 DML 权限，独立迁移完成后设置 spring.flyway.enabled=false。

~~~bash
mysql -h 127.0.0.1 -u blindbox -p blindbox
~~~

预期进入 SQL 提示符，SELECT DATABASE() 返回 blindbox。失败时核对 host 匹配、密码、端口和授权。

## 4. 配置本机 Redis

启动已有 Redis，或使用第 10 节容器。正式部署配置密码并限制网络访问，不公开 6379。

~~~bash
redis-cli -h 127.0.0.1 -p 6379 ping
~~~

无密码时预期 PONG。有密码时通过临时终端变量输入，避免写在命令参数：

~~~bash
read -s REDISCLI_AUTH
export REDISCLI_AUTH
redis-cli -h 127.0.0.1 -p 6379 ping
unset REDISCLI_AUTH
~~~

后端 .env 的 REDIS_PASSWORD 必须一致。Redis 不可用时商品缓存可回源，受限写接口返回 503，不绕过限流交易；所有读接口仍需要数据库。

## 5. 后端 .env 与启动

项目根目录：

~~~bash
cp blindbox-springboot/.env.example blindbox-springboot/.env
~~~

编辑配置：

| 参数 | 本机设置与说明 |
|---|---|
| DB_URL | jdbc:mysql://localhost:3306/blindbox?...，库须存在 |
| DB_USER / DB_PASSWORD | 第 3 节账号密码 |
| REDIS_HOST / REDIS_PORT | localhost / 6379 |
| REDIS_PASSWORD | 有密码时填写，无密码时空 |
| JWT_SECRET | 独立随机密钥，至少 32 字节，替换占位符 |
| JWT_HOURS | 默认 2，允许 1–24 |
| DEMO_RECHARGE_ENABLED | 开发演示可 true，生产 false |
| RATE_LIMIT_ENABLED | 正常 true；隔离性能测试可 false，仅关闭 Redis 额度，保留本机准入 |
| UPLOAD_DIR | 默认后端工作目录下 uploads |
| DB_POOL_SIZE | 默认 16，根据压测调整 |
| CORS_ORIGINS | 默认 http://localhost:5173 |
| SERVER_PORT | 默认 8080 |
| HTTP_MAX_INFLIGHT | 默认 64，本机 API 在途上限 |
| DRAW_MAX_INFLIGHT / DRAW_MAX_PER_POOL | 默认 8 / 1；全局抽奖预算不超过 JDBC 上限一半 |
| ENTRY_READ_PER_MINUTE / ENTRY_WRITE_PER_MINUTE / ENTRY_AUTH_PER_MINUTE | 默认 6000 / 120 / 20，连接来源分钟额度 |

生成密钥，复制到本地 .env：

~~~bash
openssl rand -hex 32
~~~

Spring 不自动读取 .env。提供的加载脚本不使用 shell eval（URL 的 & 无需 shell 转义），不会打印凭据：

~~~bash
python3 scripts/run-backend.py
~~~

**此时才连接数据库并执行 Flyway。** 空库执行 V1–V4。预期迁移成功、端口 8080 启动。检查：

~~~bash
curl -i http://localhost:8080/actuator/health
curl -i http://localhost:8080/api/blindboxes
~~~

健康时返回 200，初始列表为空。health 包含数据库和 Redis；Redis 不通时可能为 503，即使缓存能回源。

构建/测试不需要启动部件或填写密钥：

~~~bash
cd blindbox-springboot
mvn -s .mvn/settings.xml test
mvn -s .mvn/settings.xml package
~~~

首次需下载依赖。settings.xml 指向官方 Maven Central。构建后从项目根目录运行 python3 scripts/run-backend.py --jar。

## 6. 旧 MySQL 数据升级

先备份并恢复到另一测试库，不能对唯一旧库直接启动：

~~~bash
mysqldump -u root -p --single-transaction blindbox > blindbox-before-upgrade.sql
~~~

核对旧库与 V1 的六张表一致。没有 Flyway 历史表的非空库默认拒绝自动迁移，这是预期行为。确认结构一致后，仅对恢复出的测试库第一次启动时设置：

~~~bash
SPRING_FLYWAY_BASELINE_ON_MIGRATE=true SPRING_FLYWAY_BASELINE_VERSION=1 python3 scripts/run-backend.py
~~~

成功后取消临时变量。baseline 是声明旧库已经完成 V1，不是结构检查或修复。结构不同应编写专门迁移，不强行 baseline。

V2 保留余额与订单，补订单快照和 legacy-* 请求号；旧总库存存入 legacy_stock，当前 stock 清零、奖品 stock=0、商品 DRAFT。旧数据没有各款剩余数量，不能由概率反推。旧 probability 移除；按真实数量补货后才能上架。

V3 检查非负库存、合法价格/角色/稀有度；历史异常会导致迁移失败。MySQL DDL 不保证整个迁移事务回滚，失败后不要盲目 repair，应在备份恢复的测试库修正再验证。V4 增加管理员建池幂等字段。

SQLite 与旧 Node 数据不在自动迁移范围，需另行映射，尤其旧样例价格按元，新接口按分。

## 7. 创建管理员与开发样例数据

后端启动后注册自选账号：

~~~bash
curl -i http://localhost:8080/api/auth/register -H 'Content-Type: application/json'   -d '{"account":"your-admin-account","password":"choose-your-own-password"}'
~~~

账号 3–50 字符，新注册密码 8–64 字符且UTF-8最多72字节，登录保留旧短密码兼容。注册仅创建 USER，不接受自选角色。数据库确认目标账号后：

~~~sql
UPDATE user SET role='ADMIN' WHERE account='your-admin-account';
~~~

网页登录后有管理工作台。每个请求读取数据库角色，降权也在后续请求生效。

管理界面可直接创建奖池：名称、系列、价格（元）、描述，逐个配置奖品图片、稀有度、数量，保存为 DRAFT 后上架。无需填写固定概率。

或在已有 ADMIN 的开发库导入样例：

~~~bash
mysql -u blindbox -p blindbox < scripts/dev-seed.sql
~~~

预期 configured_fixture_boxes=4，四系列各 100 份，样例初始配货 30/30/20/15/5。它不会自动导入；相同管理员下重复导入不会补回已消耗库存。更换管理员后再次导入可能产生新样例，不把该脚本当正式运营初始化。

## 8. 前端启动与业务联调

~~~bash
cd BlindBox-frontend
npm ci
npm run dev
~~~

浏览器 Network 中 /api/blindboxes 应为 200，原有图片从 /images 读取，上传从 /uploads 读取。开发库开启 DEMO_RECHARGE_ENABLED=true 后重启后端，账户可增加演示余额；这并非真实支付。输入 100.00 元提交 amount=10000。

顺序验收：

1. 注册/登录；响应不含 password；普通用户访问管理 API 为 403。
2. 管理员创建、补货、上架；售罄或总库存不一致不能上架。
3. 抽奖后余额减少价格，总库存和中奖款各减 1，订单/资金/库存流水各新增一条。
4. 刷新详情，概率变化；库存为 0 的奖品概率为 0。
5. 同 key 重复抽奖返回同 orderId；换盲盒为 409。
6. 刷新网页后可恢复待确认抽奖，超时不创建另一请求。
7. 上传真实 PNG/JPEG、发布晒单、点赞/取消、分页评论。

抽奖 API（TOKEN 和 KEY 由你填写，KEY 是 8–64 位字母数字或 -/_）：

~~~bash
curl -i -X POST http://localhost:8080/api/blindboxes/1/draw   -H "Authorization: Bearer $TOKEN" -H "Idempotency-Key: $KEY"   -H 'Content-Type: application/json' -d '{}'
curl -i http://localhost:8080/api/orders/request/$KEY -H "Authorization: Bearer $TOKEN"
~~~

默认每分钟认证 20 次/连接 IP，抽奖 10 次/用户，充值 5 次，上传 6 次，其他写 30 次。429 的 Retry-After=60 是保守等待时间。固定窗口边界可突发。

Nginx/Vite 后端看到代理 IP，所有来源窗口会按该代理聚合；Nginx 模板另按浏览器 IP 限流。如需后端真实来源 IP，只在可信代理配置完成后启用转发头处理，不信任任意客户端 X-Forwarded-For。

## 9. 真实并发与故障验收（当前未执行）

专用测试库，记录硬件、版本、并发用户/奖池、连接池和限流配置。

| 场景 | 必须检查 |
|---|---|
| 同请求并发 20 次 | 部分请求可能503；保留同key重试恢复，最终一笔订单、一次扣款、一次扣库存 |
| 20 份，100 不同请求 | 成功订单≤20，无负库存；足额并重试后可抽完20份 |
| 同用户跨奖池 | 余额不透支、扣款失败无订单 |
| 充值与抽奖并发 | 不覆盖更新，资金变化可对账 |
| 补货/下架与抽奖并发 | 总库存与各款之和一致 |
| 订单/流水写入故障 | 库存、余额、订单及流水全部回滚 |
| 提交成功、响应超时 | 同 key 仍返回原订单 |
| Redis 不可达 | 受保护写503，不出现另一套库存 |
| 两后端实例 | Redis限流共享，数据库幂等生效 |
| 抽完整池 | 各奖品中奖次数精确等于初始配货 |

Mock 不证明真实数据库事务和锁。故障注入可在隔离测试库用临时触发器拒绝某测试用户订单插入，比对前后余额、库存、流水；不要对业务库操作。

只读对账：

~~~bash
mysql -u blindbox -p blindbox < scripts/audit.sql
~~~

异常查询预期为空。legacy-* 旧订单无新流水，脚本排除；旧余额是期初余额，不声称已重建历史账本。

可选 k6：

~~~bash
RUN_LOAD_TEST=YES RUN_ID=unique-run USER_TOKENS=token1,token2 BOX_ID=测试奖池ID VUS=10 ITERATIONS=100 k6 run scripts/draw-load.js
~~~

脚本会真实消耗余额库存，只用于隔离开发库。用户先充值；交易性能测试可临时关闭限流，保护机制测试保持开启。脚本分别记录业务冲突、限流、繁忙和成功，并检查重放；这些不代表业务验收通过，须分析成功吞吐和数据库对账。目前无实测 QPS。

## 10. Docker Compose 模板（本轮未执行）

项目根目录：

~~~bash
cp infra/.env.example infra/.env
~~~

填写独立密码与 JWT 密钥，再运行：

~~~bash
docker compose --env-file infra/.env -f infra/compose.yml up -d mysql redis
docker compose --env-file infra/.env -f infra/compose.yml ps
docker compose --env-file infra/.env -f infra/compose.yml up -d --build backend frontend
~~~

访问 http://localhost:8088。模板只绑定本机端口，MySQL/Redis/backend 不直接公开。镜像版本在部署前复核补丁并固定摘要。容器应用非 root；uploads 是持久化卷，主机方式使用自己的可写目录。

进入数据库建立管理员：

~~~bash
docker compose --env-file infra/.env -f infra/compose.yml exec mysql mysql -u root -p blindbox
~~~

停止但保留数据：

~~~bash
docker compose --env-file infra/.env -f infra/compose.yml stop
~~~

保留 mysql-data、redis-data、uploads，不用 down -v 重启。跨主机多实例要共享上传存储或对象存储，单机命名卷不代表跨主机共享。

## 11. 正式部署前

完成迁移恢复、并发和故障验收；关闭开发充值；独立接入真实支付验签/金额核验/幂等回调/支付对账。配置 HTTPS、敏感部件网络隔离、备份恢复、账号权限分离、密钥管理、日志脱敏和补丁更新。

监控延迟/错误原因、Hikari等待、MySQL锁等待/死锁、Redis延迟、磁盘；不公开敏感 Actuator。交易只读主库，不从延迟副本计算实时概率。容器模板尚未实际验证，不等于已部署。

## 12. 常见问题

| 现象 | 排查 |
|---|---|
| JWT_SECRET 无法解析 | .env 未加载，使用 Python 启动器/IDE环境/Compose |
| 非空库无history | 先核查旧结构和备份，再有条件baseline |
| 商品库存为0 | 旧库尚未按各款重新配货 |
| 登录503 | Redis限流或数据库认证查询不可用 |
| 无管理入口 | role是否ADMIN、刷新用户信息 |
| 401 | token过期、密钥变化，旧Express token不能混用 |
| 图片404 | assets复制、Vite/Nginx代理、上传目录 |
| 商品名称或新上架列表短暂旧值 | 元数据异步失效，条目TTL120秒；库存/状态/价格另查库 |
| 抽奖503繁忙 | 全局/同用户/同池准入或数据库繁忙，保留原key稍后重试 |
| 429 | 用户限额、代理IP聚合、Nginx入口保护 |
| 409 | 看msg：余额、售罄、状态、库存或幂等冲突 |

官方参考：[MySQL锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)、[Redis Lua](https://redis.io/docs/latest/develop/programmability/eval-intro/)、[Spring Security认证结构](https://docs.spring.io/spring-security/reference/servlet/authentication/architecture.html)。

并发保护的配置、代理来源额度、指标与压测解释见 [并发优化说明](并发优化说明.md)。
