# BlindBox 升级开发文档

创建：2026-10-12；并发方案更新：2026-10-13。后端沿用 `blindbox-springboot`，前端沿用 `BlindBox-frontend`；旧 Express 后端仅保留历史参考。初次升级不联调；后续已按要求完成数据导入，本轮并发改动不修改交易数据、不部署、不推送。

## 1. 目标与边界

实现库存驱动的有限奖池、可靠同步抽奖事务、请求幂等、资金和库存流水、服务端管理员授权、Redis 缓存与限流、商品运营与社区功能，并重构前端界面。复用根目录 `images/*.png`，构建时同步到前端 public/images。真实支付、物流、退款、Redis 库存预占和 MQ 异步交易不属于已实现功能；这些扩展必须单独设计状态机与恢复机制。

完成后交付：源码、迁移脚本、开发和部署配置模板、独立单元测试、待执行的联调/压测步骤、完整接入指南和面试说明。所有验证区分“已执行的离线检查”和“待接入的集成验证”。

## 2. 核心业务约束

- 每一个剩余实体奖品等机会被抽中，`P(奖品 i)=stock_i/sum(stock)`；稀有度概率是同稀有度库存之和占比。
- 抽奖是无放回抽样，概率随剩余库存变化；不配置固定中奖率、保底或最后奖品兜底。
- `blind_box.stock = SUM(prize.stock)`；创建、补货、抽奖全部通过受控事务维护。
- 金额在接口及数据库均使用整数分，前端负责显示元；余额更新和流水写入同事务。
- 一个 `(user_id, request_id)` 至多产生一个订单；同一个请求 ID 换盲盒返回冲突。
- 成功订单、奖品扣减、盲盒扣减、资金扣减、两类流水全部提交或全部回滚。
- 奖品及商品采用上下架/归档，历史订单保留名称、图片和稀有度快照。
- 缺失各款库存的历史商品不可自动按概率推算；迁移标记为待配货，管理员通过补货完成后才能上架。

## 3. 架构与高并发方案

React → 同源 `/api` → 本机入口并发保护/Redis 来源窗口 → JWT/角色 → Redis 用户窗口 → Controller → 非事务 DrawService 准入 → 独立事务 DrawTransactionService → MyBatis → MySQL。

MySQL 为资金及库存唯一事实来源。抽奖事务固定先锁用户行、后锁盲盒行，再锁定读取奖品库存；同用户请求和同奖池抽奖串行，不同用户的不同奖池可并行。读取库存和选奖在锁保护内，不能在锁外按旧概率抽奖。条件扣款、条件扣库存必须检查影响行数。数据库事务不调用外部支付或上传服务。

Redis 仅缓存商品元数据和执行限流，不持有可独立扣减的库存，不缓存交易余额。元数据条目 TTL 为 120 秒；列表每次批量查当前库存、状态和价格，详情用单条普通 SELECT 取得一致 MVCC 快照，不争抢库存写锁。抽奖/补货不失效元数据，商品信息变更在提交后经有界执行器异步失效。缓存缺失用锁条带合并加载，等待最多 50ms；缓存故障可回源，Redis 限流故障时写请求返回 503。事务前准入默认全局 8、同池 1、同用户 1，在事务提交/回滚后释放；超额快速拒绝而不借用 JDBC 排队。详情见 [并发优化说明](../../docs/并发优化说明.md)。单热门奖池仍受数据库行锁上限约束，容量必须压测。

## 4. 数据模型

保留 user、blind_box、prize、orders、player_show、comment；增加 wallet_ledger、stock_ledger、player_show_like。用户新增 role；商品新增 status；奖品新增 stock；订单新增 request_id 及快照。金额采用 BIGINT，非负条件与业务上限双重校验。订单查询使用快照分页，收藏统计数据库聚合。点赞唯一键 `(user_id, player_show_id)`，取消点赞与计数同步事务执行。

迁移采用 Flyway：V1 建立兼容旧表结构，V2 增加字段和业务表，V3 添加数据约束，V4 添加建池幂等字段；不自动 baseline 现有未知数据库。样例数据独立 SQL，仅对空的开发库手动导入。

## 5. 接口契约

统一响应 `{code,msg,data}`，code 与 HTTP 状态一致；400 参数错误、401 未认证、403 无权限、404 不存在、409 请求冲突或库存冲突、429 限流、503 保护组件不可用。所有分页限制 pageSize≤100。

| 业务 | 接口 |
|---|---|
| 认证 | POST /api/auth/register、/login；GET /api/user/info |
| 商品 | GET /api/blindboxes；GET /api/blindboxes/{id} |
| 抽奖 | POST /api/blindboxes/{id}/draw，必带 Idempotency-Key |
| 结果恢复 | GET /api/orders/request/{requestId} |
| 订单/收藏 | GET /api/orders；GET /api/user/collection |
| 开发充值 | POST /api/user/recharge，必带 Idempotency-Key，默认禁用 |
| 社区 | GET/POST /api/playershows；POST/DELETE /{id}/like；GET /POST /{id}/comments |
| 上传 | POST /api/images，只允许认证用户上传已校验图片 |
| 管理 | GET/POST /api/admin/blindboxes；PUT /{id} 更新介绍与价格；PATCH /{id}/status；POST /{id}/restock；DELETE /{id} 归档 |

## 6. 前端设计

暖白色底、墨色文字、绿色主操作，采用收藏商店风格，包含导航、系列筛选、图片主视觉、商品卡片、奖品概率列表、抽奖结果层、账户收藏、订单、社区与管理员工作台。海洋/森林/太空/糖果均引用已有图片。移动端响应式、键盘可操作、错误/空/加载状态完整。

不使用虚构销量或交易数据。离线预览仅展示明确标注的样例商品和图片，不支持模拟扣款或抽奖。API 不可达时展示连接错误。交易超时保存请求 ID，允许查询及同 ID 重试；结果未确认前禁止创建新请求。

## 7. 安全与配置

JWT 密钥、数据库密码、Redis 密码由环境变量注入；管理员角色在服务端查询并授权；生产禁止开发充值。上传验证图片实际编码、尺寸、大小，生成受控扩展名；本地文件服务目录持久化，生产可替换对象存储。Spring Security 对公开 GET 和写请求分别授权。日志不记录密码、JWT 或上传字节。
